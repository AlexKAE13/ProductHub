# Product HUB - правила проекта

Внутреннее веб-приложение Eltex: единая база знаний по продуктам (SKU) и база артефактов отдела. Полное ТЗ в SPEC.md, текущее состояние в STATUS.md.

## Как работаем

- Работаем строго по этапам из SPEC.md, раздел 9. Один этап за сессию. Не делать работу следующих этапов заранее.
- Перед началом этапа прочитать SPEC.md (нужные разделы) и STATUS.md. Сначала показать план: какие сущности, миграции, страницы, тесты. Реализовывать после подтверждения.
- Если в ТЗ чего-то не хватает или есть противоречие, спросить. Мелкие технические решения принимать самому и записывать в STATUS.md, раздел "Решения".
- В конце этапа: `./mvnw verify` проходит, критерии готовности этапа проверены, STATUS.md обновлен (что сделано, как проверено, замеры скорости, известные проблемы).
- Пользователь - продакт-менеджер, не Java-разработчик. Объяснять коротко и по делу, без жаргона там, где можно без него. Команды для запуска давать готовыми к копированию.

## Стек

- Java 21, Spring Boot (последняя стабильная), Maven wrapper.
- Spring MVC + Thymeleaf + HTMX. SortableJS для канбана. JS-файлы лежат локально в `src/main/resources/static/vendor`, без CDN и без Node.
- Spring Data JPA, Flyway, H2 (профиль dev, файл в `./data`), PostgreSQL (профиль prod).
- Spring Security, роли из SPEC.md раздел 2.
- Lucene (напрямую, без Hibernate Search) для поиска (с этапа 5).
- Apache POI для импорта Excel.
- Caffeine для кэша справочников.
- Не добавлять новые зависимости без причины. Если нужна новая библиотека, сказать зачем.

## Команды

- Запуск: `./mvnw spring-boot:run` -> http://localhost:8080
- Тесты: `./mvnw verify`
- Сброс локальных данных: удалить папку `./data`

## Структура

- Пакет `ru.eltex.producthub`, раскладка по модулям (SPEC.md 3.1): tag, sku, artifact, firmware, casestudy, qa, task, search, dashboard, importer, security, common, web.
- Внутри модуля: domain, repo, service, web.
- Бизнес-логика только в сервисах. Контроллеры тонкие. Модули общаются через события Spring (SPEC.md 3.2).
- Шаблоны: `src/main/resources/templates/<модуль>/`. Общий layout: `templates/layout.html`. HTMX-фрагменты в тех же шаблонах через `th:fragment`.
- Тексты интерфейса только через `messages_ru.properties`.

## Правила кода

- Схема БД меняется только новой миграцией Flyway. Примененные миграции не редактировать. SQL должен работать и в H2 (MODE=PostgreSQL), и в PostgreSQL.
- Права проверять в сервисах, а не только скрывать кнопки. Контур (INTERNAL или EXTERNAL) учитывать при любой выдаче данных.
- Без N+1 в карточке SKU и в списках. Тест со счетчиком SQL-запросов на карточку.
- Удаление мягкое (флаг deleted).
- Изменения SKU, артефактов, прошивок, кейсов, тегов пишутся в AuditLog.
- Файлы сохраняются через интерфейс FileStorage, на диске под UUID-именами.
- Папку `seed/` не изменять, это исходные данные. Импорт читает их как есть.
- Тесты пишутся на бизнес-правила, права, триггеры задач, импорт (на реальных файлах из seed), нормализацию артикулов.

## Интерфейс

- Простой нейтральный стиль: белый фон, оттенки серого, один спокойный акцентный цвет. Без градиентов, теней-эффектов, ярких цветов и тяжелых UI-китов.
- Плотная информативная верстка, удобная для работы, а не для красоты. Таблицы читаемые, шрифт системный.
- Цветом выделять только статусы (ЖЦ, актуальность материала, задачи).
- Текст интерфейса на русском. Вместо длинного тире использовать короткое "-". Букву "ё" не использовать, писать "е".

## Темы оформления

- Две темы, выбор личный (настройки пользователя): современная (по умолчанию: хвоя, градиент; стекло, схемы, обои) и классическая (строгая).
- Классика живет в `static/css/app.css`. Современная - отдельный `static/css/modern.css`, подключается только если выбрана; он переопределяет переменные и добавляет стекло. Не смешивать правила тем в одном файле.
- Новую страницу или компонент проверять в обеих темах. Цвета статусов (ЖЦ, актуальность, задачи) только через `--st-*`, не от акцента.
- Макет-эталон современной темы: `design/modern-mockup.html`; скелетоны загрузки есть в обеих темах (`static/js/skeleton.js`).

## Скорость

Цели из SPEC.md 8.1 обязательны: каталог до 200 мс, карточка до 300 мс, поиск до 100 мс. Время ответа видно в подвале страницы и в заголовке Server-Timing. Если изменение замедляет страницу, это ошибка.
