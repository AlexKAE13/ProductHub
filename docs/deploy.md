# Product HUB: инструкция для ИТ

Внутреннее веб-приложение Eltex (база знаний по продуктам). Поставляется как Docker-образ вместе с PostgreSQL.

## 1. Требования к серверу

| Что | Минимум |
|---|---|
| ОС | Linux (любой дистрибутив) или другая система с Docker Engine 24+ и Docker Compose v2 |
| Процессор, память | 2 ядра, 4 ГБ ОЗУ (приложение занимает до 70% памяти контейнера, PostgreSQL около 0,5 ГБ) |
| Диск | 20 ГБ + место под материалы (файлы пользователей лежат в томе `app-data`, база в томе `db-data`) |
| Сеть | Порт 8080 (меняется `PRODUCTHUB_PORT`) для пользователей, доступ из контейнера приложения к серверу AD/LDAP (389 или 636) |
| Доступ в интернет | Нужен только при сборке образа (скачиваются Java и библиотеки). Для работы не нужен: JS и стили лежат внутри приложения |

HTTPS: приложение отдает HTTP. Для HTTPS поставьте перед ним обратный прокси компании (nginx, Traefik и т.п.), который передает заголовки `X-Forwarded-*`.

## 2. Установка

1. Скопируйте на сервер папку проекта (или клонируйте репозиторий).
2. Скопируйте `.env.example` в `.env` и заполните (минимум `PRODUCTHUB_DB_PASSWORD`).
3. Положите исходные данные для первого импорта в папку `seed/` рядом с `docker-compose.yml` (реестр ЖЦ, каталог сайтов, реестр типов документов; состав как в репозитории). Папка подключается только на чтение.
4. Запустите:

```bash
docker compose up -d --build
```

5. Проверьте состояние: `curl http://localhost:8080/actuator/health` отвечает `{"status":"UP"}`. Контейнеры `app` и `db` имеют встроенные проверки состояния (`docker compose ps` показывает `healthy`).
6. Войдите и нажмите в разделе "Справочники" "Запустить импорт" (кнопка видна администратору).

Первый запуск создает схему базы сам (миграции Flyway). Данные пользователей хранятся в PostgreSQL, файлы в томе `app-data` (`/data/files`), индекс поиска в `/data/index` (его можно удалить, он перестроится сам).

## 3. Вход через AD/LDAP

Включается в `.env`: `PRODUCTHUB_LDAP_ENABLED=true` и параметры каталога (см. `.env.example`). Пароль проверяет каталог, приложение паролей не хранит.

| Параметр | Что это | OpenLDAP | Active Directory (пример) |
|---|---|---|---|
| `PRODUCTHUB_LDAP_URL` | адрес сервера | `ldap://host:389` | `ldap://dc.company.local:389` или `ldaps://...:636` |
| `PRODUCTHUB_LDAP_BASE` | корень каталога | `dc=example,dc=local` | `dc=company,dc=local` |
| `PRODUCTHUB_LDAP_MANAGER_DN` / `_PASSWORD` | служебная учетная запись только на чтение (для поиска пользователей и групп) | `cn=hub-reader,...` | `CN=svc-hub,OU=Service,...` |
| `PRODUCTHUB_LDAP_USER_SEARCH_BASE` | где искать пользователей, относительно корня | `ou=people` | `OU=Users` |
| `PRODUCTHUB_LDAP_USER_SEARCH_FILTER` | как найти по логину | `(uid={0})` | `(sAMAccountName={0})` |
| `PRODUCTHUB_LDAP_LOGIN_ATTRIBUTE` | атрибут с логином | `uid` | `sAMAccountName` |
| `PRODUCTHUB_LDAP_NAME_ATTRIBUTE` | полное имя | `cn` | `displayName` |
| `PRODUCTHUB_LDAP_GROUP_SEARCH_BASE` | где искать группы | `ou=groups` | `OU=Groups` |
| `PRODUCTHUB_LDAP_GROUP_SEARCH_FILTER` | как найти группы пользователя | `(member={0})` | `(member={0})` |

**Группы и роли.** Роль в HUB определяется группами каталога. По умолчанию имена групп такие (регистр не важен):

| Группа | Роль |
|---|---|
| `hub-product` | продакт-менеджер |
| `hub-service` | сервисный центр |
| `hub-sales` | менеджер по продажам |
| `hub-rnd` | R&D, техподдержка |
| `hub-head` | руководитель |
| `hub-admin` | администратор |

Если в компании группы называются иначе, создайте файл `config/application.yml` рядом с `docker-compose.yml`:

```yaml
producthub:
  ldap:
    group-roles:
      Eltex-Product-Managers: PRODUCT
      Eltex-Product-Heads: HEAD
      Eltex-HUB-Admins: ADMIN
```

и перезапустите приложение. У человека может быть несколько групп (несколько ролей). Кто не состоит ни в одной из этих групп, войти не может. Вложенные группы AD напрямую не раскрываются: включайте людей в нужную группу или раскройте вложенность на стороне каталога.

**Логины.** Пользователь в HUB определяется логином. Если в базе уже есть пользователь с таким логином (например владелец SKU `kuznetsov`), при входе используется он, его SKU и материалы остаются за ним. Остальные пользователи создаются при первом входе. Роли обновляются при каждом входе по текущим группам.

**Проверка без боевого каталога.** В репозитории есть тестовый стенд с OpenLDAP:

```bash
docker compose -f docker-compose.yml -f ops/docker-compose.ldap-test.yml up -d --build
```

Вход: `kuznetsov` (продакт), `moiseev` (руководитель), `sales1` (продажи), `admin1` (администратор), пароль `Test1234`; `outsider` в группах HUB не состоит и войти не может. Стенд только для проверки.

## 4. Бэкап и восстановление

**Что копируется:** база PostgreSQL (дамп) и файлы пользователей (материалы, прошивки). Индекс поиска не копируется, он перестраивается сам.

```bash
./ops/backup.sh ./backups 14
```

Создает папку `./backups/ГГГГММДД-ЧЧММСС` с файлами `db.dump`, `files.tar.gz` и контрольными суммами, удаляет копии старше 14 дней. Расписание (ежедневно в 02:00), строка для `crontab -e`:

```
0 2 * * * cd /opt/product-hub && ./ops/backup.sh /srv/backups/product-hub 14 >> /var/log/product-hub-backup.log 2>&1
```

Копии нужно регулярно выносить с сервера (на сетевое хранилище).

**Восстановление** (текущие данные заменяются данными из копии):

```bash
./ops/restore.sh ./backups/20261014-020000
```

Скрипт проверяет контрольные суммы, останавливает приложение, пересоздает базу из дампа, подменяет файлы и запускает приложение. После восстановления проверьте вход и откройте несколько материалов.

Рекомендуем раз в квартал проверять восстановление на отдельной машине.

## 5. Перенос данных из пилота (H2 на рабочем компьютере -> PostgreSQL на сервере)

Пока приложение работает на компьютере продакта (профиль dev), данные лежат в папке `data`: база `data/producthub.mv.db`, файлы `data/files`. Чтобы перенести их на сервер (материалы, SKU, комментарии коллег, настройки):

1. Остановите приложение на компьютере. На сервере поднимите HUB обычным образом (раздел 2), чтобы создалась схема. Версия приложения на сервере должна быть той же, что на компьютере (иначе перенос откажется работать и скажет об этом).
2. Скопируйте файл `producthub.mv.db` на сервер в любую папку, например `/srv/import/`.
3. Выполните перенос (приложение при этом запускается один раз, переносит данные и выходит):

```bash
docker compose stop app
docker compose run --rm -T --no-deps -v /srv/import:/import:ro \
  -e PRODUCTHUB_TRANSFER_H2_FILE=/import/producthub app
docker compose start app
```

Имя файла указывается без `.mv.db`. Данные в PostgreSQL перед переносом **заменяются** (кроме истории миграций). Если что-то пойдет не так, ничего не изменится (перенос идет одной транзакцией).

4. Скопируйте файлы материалов и прошивок в том приложения:

```bash
docker compose cp ./data/files/. app:/data/files/
docker compose exec --user root app chown -R hub /data/files
```

5. Индекс поиска построится сам при запуске. Проверьте вход и откройте пару материалов.

Репетиция этого переноса на реальных данных пилота (309 SKU, 36 материалов, 627 записей о владельцах) прошла без ошибок.

## 6. Обновление

```bash
./ops/backup.sh ./backups 14     # копия перед обновлением
git pull                          # или подмените папку проекта новой версией
docker compose up -d --build
```

Схема базы обновляется автоматически при старте. Откат: восстановить копию и запустить предыдущую версию.

## 7. Журналы и мониторинг

- Журнал приложения: `/data/logs/product-hub.log` внутри тома `app-data` (ротация: файл до 20 МБ, хранится 30 дней, всего не больше 1 ГБ). Просмотр: `docker compose logs -f app`. В журнале нет паролей и персональных данных, кроме логина.
- Проверка состояния для мониторинга: `GET /actuator/health` (без входа, подробностей не показывает).
- Время ответа каждой страницы видно в подвале и в заголовке `Server-Timing`.

## 8. Порты и тома

| Что | Где |
|---|---|
| Веб-интерфейс | порт `PRODUCTHUB_PORT` (по умолчанию 8080) |
| База PostgreSQL | том `db-data`, наружу порт не открыт |
| Файлы, индекс, журналы | том `app-data` (`/data`) |
