# Product HUB

Внутреннее веб-приложение Eltex: единая база знаний по продуктам (SKU) и база артефактов отдела (даташиты, презентации, battle cards, прошивки, кейсы).

Стек: Java 21, Spring Boot 4.1.1, Thymeleaf, HTMX, Spring Data JPA, Flyway, H2 (разработка), PostgreSQL 16 (сервер), Lucene (поиск).

## Установка

### Локально (разработка)

Требуется: JDK 21, Git.

```bash
git clone https://github.com/AlexKAE13/ProductHub.git
cd ProductHub
./mvnw spring-boot:run
```

Приложение: http://localhost:8080. На первом запуске создаются схема базы (Flyway) и данные из папки `seed/` (реестр жизненного цикла, каталог сайтов, реестр типов документов). Вход через список "Войти как" (профиль `dev`).

Данные профиля `dev` лежат в `./data` (база H2, файлы, индекс поиска). Сброс: остановить приложение и удалить `./data`.

```bash
./mvnw verify            # сборка и тесты
./mvnw spotless:apply    # форматирование кода
```

Тесты на PostgreSQL (Testcontainers) требуют Docker, без него они пропускаются.

### Сервер (Docker Compose: приложение + PostgreSQL)

Требуется: Docker Engine 24+ и Docker Compose v2, 2 ядра, 4 ГБ ОЗУ, 20 ГБ диска плюс место под материалы.

1. Получить код:

```bash
git clone https://github.com/AlexKAE13/ProductHub.git
cd ProductHub
```

2. Создать файл настроек и задать пароль базы:

```bash
cp .env.example .env
```

В `.env` обязательно заполнить `PRODUCTHUB_DB_PASSWORD`. Остальные переменные описаны в разделе "Конфигурация".

3. Убедиться, что в папке `seed/` лежат три исходных файла (в репозитории они есть). Папка монтируется в контейнер только на чтение.

4. Запустить:

```bash
docker compose up -d --build
```

5. Проверить состояние:

```bash
docker compose ps
curl http://localhost:8080/actuator/health
```

Ответ `{"status":"UP"}`, контейнеры `app` и `db` в состоянии `healthy`.

6. Открыть http://localhost:8080. Первичный импорт SKU запускается автоматически при пустой базе, повторно: раздел "Справочники", кнопка "Запустить импорт" (роль ADMIN).

Вход через AD/LDAP включается переменными `PRODUCTHUB_LDAP_*`, соответствие групп ролям задается в `config/application.yml`. HTTPS обеспечивает обратный прокси перед приложением. Подробности, резервное копирование, восстановление, перенос данных из пилота и обновление: [docs/deploy.md](docs/deploy.md).

## Конфигурация

Профили Spring:

| Профиль | Назначение |
|---|---|
| `dev` (по умолчанию) | H2 в `./data`, вход через список "Войти как" |
| `lan` | Добавляется к `dev`: порт 7777, адрес 0.0.0.0, тестовые учетные записи скрыты, импорт папок с диска отключен |
| `perf` | Данные для замера скорости (300 SKU, 5000 артефактов, 300 прошивок, 100 кейсов), отдельная база в `./data-perf` |
| `prod` | PostgreSQL, вход через AD/LDAP, настройки из переменных окружения (задается в образе) |

```bash
SPRING_PROFILES_ACTIVE=dev,lan ./mvnw spring-boot:run
SPRING_PROFILES_ACTIVE=dev,perf SERVER_PORT=8081 ./mvnw spring-boot:run
```

Переменные окружения (шаблон: `.env.example`):

| Переменная | Назначение |
|---|---|
| `PRODUCTHUB_DB_PASSWORD` | Пароль PostgreSQL (обязательна) |
| `PRODUCTHUB_PORT` | Порт приложения, по умолчанию 8080 |
| `PRODUCTHUB_LDAP_ENABLED` | Вход через AD/LDAP (`true` или `false`) |
| `PRODUCTHUB_LDAP_URL`, `_BASE`, `_MANAGER_DN`, `_MANAGER_PASSWORD` | Подключение к каталогу |
| `PRODUCTHUB_LDAP_USER_SEARCH_BASE`, `_USER_SEARCH_FILTER`, `_LOGIN_ATTRIBUTE`, `_NAME_ATTRIBUTE`, `_MAIL_ATTRIBUTE` | Поиск пользователей |
| `PRODUCTHUB_LDAP_GROUP_SEARCH_BASE`, `_GROUP_SEARCH_FILTER` | Поиск групп |

Тома Docker: `db-data` (PostgreSQL), `app-data` (`/data`: файлы материалов, индекс поиска, журналы).

## Документация

### Разделы

| Раздел | Назначение |
|---|---|
| Каталог | Список SKU, фильтры (семейство, линейка, статус жизненного цикла, владелец), заполненность карточек |
| Карточка SKU | Характеристики, жизненный цикл, материалы по связям (документация, сравнения, battle cards, фото и видео), прошивки, кейсы, вопросы и ответы |
| Артефакты | База материалов отдела: тип, язык (RU, EN, RU_EN), статус, контур, версии файлов, срок ревью, привязка к SKU и линейкам, теги, массовые действия |
| Прошивки | Публикация прошивок, release notes, контрольная сумма sha256 |
| Кейсы | Кейсы заказчиков, привязка к SKU, скрытое имя заказчика |
| Задачи | Канбан: Новые, В работе, На проверке, Закрыто |
| Дашборд | Покрытие карточек, устаревание материалов, вопросы, задачи, спрос |
| Справочники | Теги, типы артефактов, шаблоны, импорт, переиндексация поиска |
| Правки | Комментарии к интерфейсу, выгрузка в файл |
| Настройки | Личные настройки пользователя, тема оформления (классическая или современная) |

### Основные правила

- **Единый источник правды.** Материал хранится один раз и показывается в карточках SKU по связям (SKU, линейка, теги). Новая версия файла становится текущей, старые остаются в истории.
- **Контур.** Каждый материал помечен INTERNAL или EXTERNAL. Во внешний контур попадают только материалы, помеченные EXTERNAL.
- **Ревью.** У материала и SKU есть срок ревью. По истечении срока владельцу создается задача, статус материала автоматически не меняется.
- **Вопросы и правки.** Любой пользователь задает вопрос или предлагает правку к SKU и материалу, ответ и принятие правки делает владелец.
- **Задачи по триггерам.** Задачи создаются автоматически: публикация прошивки (проверка даташита, battle card, сайта), новый вопрос, предложенная правка, просроченное ревью, смена статуса SKU на EOL_ANNOUNCED, загрузка материала RU без пары EN (и наоборот).
- **Поиск.** Строка в шапке: подсказки от 2 символов, нормализация артикулов (`wep550k`, `WEP 550K` и `wep-550k` дают WEP-550K), морфология RU и EN, опечатки, учет контура.
- **Импорт.** Excel из `seed/` и папки с материалами (предпросмотр, dry-run, без дублей по sha256). Журнал каждого импорта.
- **Аудит.** Изменения SKU, артефактов, прошивок, кейсов и тегов пишутся в журнал. Удаление мягкое.

### Роли

| Код | Роль | Права |
|---|---|---|
| PRODUCT | Продакт-менеджер | Создание и правка SKU, материалов, прошивок, кейсов, тегов, ответы на вопросы, задачи, дашборд по своим линейкам |
| SERVICE_CENTER | Сервисный центр | Технические блоки карточки, прошивки, загрузка материалов, технические вопросы |
| SALES | Менеджер по продажам | Чтение, скачивание, поиск, вопросы и предложения правок |
| RND | R&D, техподдержка | Чтение, вопросы, публикация прошивок |
| HEAD | Руководитель | Чтение, дашборд по всем данным |
| ADMIN | Администратор | Пользователи, роли, справочники, импорт |
| PARTNER | Партнер | Только внешний контур, не реализован |

Права проверяются в сервисах. Полная матрица: `SPEC.md`, раздел 6.

### Скорость

Цели (95-й перцентиль): каталог до 200 мс, карточка SKU до 300 мс, поиск до 100 мс, канбан до 200 мс. Время ответа выводится в подвале страницы и в заголовке `Server-Timing`.
